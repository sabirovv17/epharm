# Аптека со склада → Epharm: каталог, только чтение

Самостоятельный экспортер полного справочника сайта с отдельным признаком публикации каждой позиции. Он не меняет код сайта, существующие таблицы и маршруты. Источник на `10.10.1.80`: PostgreSQL контейнер `aptekasosklada-v24-postgres`, сеть `aptekasosklada-v24-backend`.

## Контракт

Оба маршрута требуют `Authorization: Bearer <EXPORT_TOKEN>` (минимум 32 символа). Сервис не стартует без `DATABASE_URL` и ключа. Одновременно допускается один экспорт; второй получает `429`.

- `GET /health` → `200` JSON `{ "status":"ok", "schemaVersion":1, "catalogRunId":"...", "catalogCount":29326, "availabilityRunId":"..." }`; `503`, если нет опубликованного каталога или БД недоступна.
- `GET /v1/snapshot` → `200 application/x-ndjson`: строка `header`, затем `catalogCount` строк `product` по возрастанию `sku`, затем строка `footer`. Все строки одного `REPEATABLE READ READ ONLY` снимка PostgreSQL. Если соединение оборвалось или футер отсутствует, импорт нужно отвергнуть целиком.

`header`: `type`, `schemaVersion`, `catalogRunId`, `availabilityRunId` (`null`, если нет опубликованного соответствующего запуска), `catalogCount`, `catalogGeneratedAt`, `availabilityFinishedAt`, `availabilityValidUntil`.

`product`: `type`, `sku`, `productId`, `variantId`, `product` (нормализованная JSON-карточка с наложенными текущими ценой и индексом доступности), `priceAmount` (эффективная цена в тенге с точностью источника до двух знаков либо `null`), `published` (есть вариант и положительная цена), `aliasIds` (отсортированные подтверждённые старые Medusa `product_id` из включённой ручной таблицы соответствий). `published` соответствует критерию сайта `isVisibleCatalogProduct`. Устаревшая доступность помечается `product.stockStale`; отдельная цена каталога при этом может оставаться положительной. Потребитель хранит цену как `numeric(18,2)`; при переводе в прежний целочисленный контракт Epharm применяется явное округление `HALF_UP`.

`footer`: `type`, `productCount`, `sha256`. Хэш вычислен по **точным UTF-8 байтам всех сериализованных строк `product`**, включая `\n` после каждой; `header` и `footer` в хэш не входят. Принимать снимок следует только после проверки числа строк, хэша и уникальности `sku`, затем атомарно менять активную версию каталога в Epharm.

В опубликованной карточке сайта политика рецептурности может дополнительно обновлять `prescription` и `rx`-бейдж из отдельного справочника. Экспортер берёт эти два поля из сохранённого нормализованного снимка; они не влияют на `published` или цену. Для юридически значимых правил продажи сохраняйте отдельную проверку рецептурности в своём сервисе.

## Подготовка и запуск на .80

1. Проверить актуальные `daribar_catalog_state`, `daribar_availability_state`, количество строк и последнюю проверенную резервную копию PostgreSQL. Текущий PG контейнер не публикует порт наружу; новый сервис подключается к его Docker сети.
2. В нужной БД выполнить `role.sql` администратором, затем интерактивно `\password eshop_catalog_exporter`. Это только новая роль и `SELECT` на семь таблиц; права существующих сервисов не меняются. Проверить под новой ролью `SELECT` и отказ в `INSERT`.
3. Создать `.env` с правами `0600` **на сервере**: `DATABASE_URL=postgresql://eshop_catalog_exporter:<password>@aptekasosklada-v24-postgres:5432/inkar_cms_production_20261001` и случайный `EXPORT_TOKEN` длиной не менее 32 символов. Не копировать `.env` в Git и не выводить ключ в логи. Учитывать URL-кодирование спецсимволов пароля.
4. `docker compose -f compose.example.yml up -d --build`; дождаться `healthy`. Контейнеру дано 0.5 CPU, 256 MiB, два соединения PG и один одновременный поток экспорта. Порт публикуется только на интерфейсе `10.10.1.80:13105`, без изменений маршрутов Caddy/Nginx.
5. До внешнего доступа ограничить входящий TCP `13105` источником `10.10.1.76`. Для Docker published ports правило должно действовать в `DOCKER-USER` с учётом DNAT (например, match `--ctorigdst 10.10.1.80 --ctorigdstport 13105`); обычное правило UFW `INPUT` само по себе не подтверждает закрытие. С .76 проверить `GET /health` и один полный экспорт; с другого хоста проверить отказ. Корпоративная сеть не заменяет ключ; для пересечения недоверенных сетей нужен TLS/туннель.
6. Потребитель .76 должен сохранять предыдущий рабочий снимок при `401/429/503`, обрыве потока, неверном числе/хэше, смене структуры или отсутствии футера. Повторять с ограниченной частотой. Сверить минимум 29 326 товаров по текущему опубликованному запуску и статистику `published` с сайтом перед переключением UI.

При сбое экспорта Epharm продолжает отдавать последнее полностью проверенное поколение и показывает его возраст/ошибку в health. Для отката к прежнему источнику в окно обратной совместимости переключают только флаг чтения Epharm и его backend image по релизному runbook. Остановить отдельно экспортер можно командой `docker compose -f compose.example.yml stop eshop-catalog-exporter`; контейнеры и таблицы сайта при этом не затрагиваются.

## Ограничения источника

Каталог Daribar публикуется ежедневно целым запуском; у строки нет надёжного `updated_at` для дельты. Доступность публикуется отдельно примерно каждые 15 минут, и старые запуски быстро удаляются. Экспортер читает обе версии в одной короткой транзакции, поэтому каждая выгрузка согласована. Старые Medusa ID не равны Daribar ID; ручная таблица соответствий покрывает только часть товаров. В нормализованном Daribar снимке сейчас нет штрихкодов. Фото — путь сайта `/api/media/daribar?sku=...`, а не переносимый абсолютный URL; Epharm должен подавать их через свой безопасный прокси или разрешённый origin.
