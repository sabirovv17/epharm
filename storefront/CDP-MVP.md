# CDP MVP для «Аптеки со склада»

Цель первого этапа — получить достоверную воронку web/Android/iOS без хранения
лишних персональных данных и без зависимости от SMS.

## События v1

- `app_opened`, `page_viewed`;
- `search_performed`, `category_viewed`, `filter_applied`;
- `product_viewed`, `pharmacy_selected`;
- `cart_item_added`, `cart_item_removed`, `checkout_started`;
- `order_submitted`, `order_confirmed`, `order_cancelled`, `order_completed`;
- `demo_session_started`, `customer_identified`;
- `push_permission_changed`, `push_opened`.

Каждое событие содержит UUID, уникальный `idempotency_key`, версию, UTC-время,
источник, `anonymous_id`/`customer_id`, session ID, свойства события и снимок
согласий. Телефон в события не передаётся. Для склейки допустим только HMAC от
нормализованного телефона с серверным секретом, который нельзя отправлять клиенту.

## Identity resolution

1. До входа создаётся уникальный anonymous ID устройства/браузера.
2. Demo-путь создаёт отдельную customer-сессию, а не общий аккаунт.
3. После идентификации backend связывает anonymous ID и customer ID с профилем.
4. Слияние профилей журналируется; события не переписываются и не удаляются.
5. Маркетинговые и push-сценарии работают только при актуальном согласии.

## Приём и доставка

- `POST /api/events` принимает батч до 50 событий и возвращает результат по каждому;
- сервер валидирует имя/версию/размер, дедуплицирует по idempotency key;
- батч с невалидными событиями отклоняется атомарно с индексами ошибок; сырое PII не сохраняется;
- продуктовые события пишутся append-only в `cdp_events`;
- интеграции получают события через `integration_outbox`, с retry и dead-letter;
- клиент хранит очередь офлайн и отправляет её после восстановления сети.

## Метрики первого релиза

- search → PDP;
- PDP → cart;
- cart → checkout;
- checkout → confirmed order;
- доля пустой выдачи поиска;
- latency/error rate Medusa и локального каталога;
- доля SKU без изображения, цены и остатка;
- повторная покупка и отмена заказа.

## Что не входит в MVP

ML-рекомендации, рекламные аудитории, автоматическое обогащение профилей и экспорт
PII. Сначала нужны полнота событий, согласия, дедупликация и контроль качества.
