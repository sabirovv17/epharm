# Админка контента (сайт + мобильное приложение)

Витринный контент (**баннеры** и **сторис**, а также подборки/промокоды) теперь живёт
на сервере и отдаётся одним API — его читают и сайт, и Flutter-приложение `apteka_flutter`.

## Что где

| Часть                 | Файл                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------- |
| Модель + дефолты      | `src/lib/content/defaults.ts`                                                         |
| Файловое хранилище    | `src/lib/content/store.ts` → пишет `.data/content.json`                               |
| API                   | `src/app/api/content/route.ts` — `GET` (публичный), `POST` (под токеном)              |
| Провайдер сайта       | `src/lib/content/ContentContext.tsx` — читает `/api/content`, кэширует в localStorage |
| Админка               | `/admin` — вкладки Баннеры / Сторис / Подборки / Промокоды / Заказы                   |
| Лента сторис на сайте | `src/components/home/StoriesRow.tsx`                                                  |

## API

- `GET /api/content` → `{ banners, stories, collections, promos, orders }`. Публичный, без кэша.
- `POST /api/content` с заголовком `x-admin-token: <ADMIN_TOKEN>` и телом полного объекта контента.
  Без верного токена → `401`.

Авторизация (исправлено после аудита): секрет — ТОЛЬКО серверный **`ADMIN_TOKEN`** (НЕ `NEXT_PUBLIC_*`,
иначе попадёт в браузерный бандл; и БЕЗ дефолта — fail-closed). Это одновременно код входа в `/admin`
(проверяется на сервере через `POST /api/admin/verify`) и токен записи в `/api/content` и `/api/upload`.
Если `ADMIN_TOKEN` не задан — любая запись отклоняется (401). **В проде задайте длинный случайный
секрет** в `.env.local`. (Полноценная сессия/cookie-авторизация — следующий шаг, см. аудит.)

## Медиа (фото + видео)

- Загрузка в админке (формы баннеров/сторис) → `POST /api/upload` (под `x-admin-token`) → файл в `public/uploads/`, отдаётся по `/uploads/<имя>`. Лимиты: фото ≤ 8 МБ, видео ≤ 60 МБ (jpg/png/webp/gif, mp4/webm/mov).
- В контенте хранятся относительные URL (`/uploads/..`) — портативно между доменами. Мобилка дорисовывает `CONTENT_BASE`.
- Баннер: приоритет показа **видео > фото > градиент** (видео — автоплей без звука, цикл). Сторис: фото в кружке + фото/видео на весь экран.
- `public/uploads/` в `.gitignore`. На serverless-ФС (Vercel) загрузка не сохранится — нужен объектный сторедж (S3/Blob); на своём сервере работает из коробки.

## Хранение

`.data/content.json` рядом с проектом (в `.gitignore`). Работает на долгоживущем Node-хосте
(`next start`, свой сервер/VPS). На **serverless** (Vercel) файловая запись эфемерна — там
замените `store.ts` на KV/БД (Vercel KV, Upstash, Postgres) с теми же `readContent`/`writeContent`.

## Подключение мобильного приложения

`apteka_flutter/lib/content.dart` тянет `GET {CONTENT_BASE}/api/content` и подменяет
баннеры/сторис; офлайн/ошибка → хардкод из `data.dart` (приложение не падает).

`CONTENT_BASE` задаётся при сборке:

```bash
# эмулятор Android (хост-петля) — значение по умолчанию:
flutter build apk --release            # → http://10.0.2.2:3210

# прод — ваш развёрнутый inkar-shop:
flutter build apk --release --dart-define=CONTENT_BASE=https://shop.example.kz
```

> HTTP (без TLS) на Android уже разрешён (cleartext) — как и для Medusa. Для прода желателен HTTPS.

## Как пользоваться

1. Открыть `/admin`, ввести PIN.
2. Вкладка **Баннеры** / **Сторис** → добавить/изменить/перетащить порядок/выключить.
3. Изменения сразу пишутся в `/api/content`. Сайт показывает их сразу, приложение — при следующем запуске/обновлении.
