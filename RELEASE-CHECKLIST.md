## 0. Что входит в релиз (определить scope!)

Экосистема — 3 модуля. **До релиза зафиксировать, что именно выкатываем:**

| Модуль                                    | Что                                        | Статус                                          |
| ----------------------------------------- | ------------------------------------------ | ----------------------------------------------- |
| **M1** Приложение фармацевта (Flutter)    | вход/профиль/баланс/каталог/загрузка чека  | ✅ код готов, ⚠️ prod-блокеры ниже              |
| **M1** Админка HQ (React)                 | 13 разделов + **Витрина каталога** (новое) | ✅ готово                                       |
| **M1** Backend (Kotlin/Spring)            | API + сверка + выплаты + прокси Medusa     | ✅ готово                                       |
| **M2** POSM-кассы (C#)                    | подсказки замен + создание pending-бонусов | ⚠️ код есть, не развёрнут на кассах             |
| **M3** Интернет-магазин (Medusa/inkar.kz) | каталог/заказы                             | 🚧 другая команда; мы только **читаем** каталог |

**Критично:** бонус фармацевту создаётся из **pending_bonus**, который вживую пишет **POSM-касса**
(M2). Сейчас pending-бонусы — из seed. **Без развёрнутого POSM «продажа → бонус» не запустится в
реальной аптеке** — будут только ручная загрузка чека + ручная модерация. Решить: релиз с кассами
или «пилот без касс» (фарма видит каталог/баланс, но бонусы начисляет HQ вручную через сверку).

## 5. Минимальный путь к релизу СЕГОДНЯ (рекомендация)

Если цель — выкатить **пилот сегодня**, минимальный безопасный набор = закрыть P0 (#1–#5):

1. `MobizonSmsSender` + ключ → фарма реально получает OTP.
2. Убрать cleartext-флаги, собрать мобилку на `https://api.epharm.kz`.
3. `flutter_secure_storage` для токенов.
4. Сменить/ротировать секреты (STOREFRONT + `.env.prod`).
5. Поднять прод-стек (`docker compose --env-file .env.prod -f docker-compose.prod.yml up -d`).

**Решение по бонусам:** если кассы (POSM) сегодня не ставим — релизим как «фарма видит каталог +
баланс + грузит чек на ручную модерацию», а pending-бонусы HQ заводит через сверку. Полный
авто-цикл «продажа→бонус» включается при развёртывании POSM на кассах (M2).
