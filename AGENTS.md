## Правила работы

- Перед правкой проверь `git status`, сохрани чужие изменения. Ищи `rg` внутри нужного модуля, читай точные диапазоны; расширяй поиск лишь при необходимости.
- Git/PR и проверки: [CONTRIBUTING.md](CONTRIBUTING.md). Короткая ветка, без прямого push в `main`; релевантные тесты и CI перед слиянием, красные проверки не игнорировать.
- Для нетривиальных задач с независимыми направлениями или рискованной проверкой применяй [team-orchestrator](.agents/skills/team-orchestrator/SKILL.md): рано делегируй полезные роли (продукт, разработка, проверка), оставляя одному агенту интеграцию. Для мелкой или строго последовательной задачи не создавай команду ради количества.
- Не меняй применённые Flyway-миграции. При изменении пользовательского потока обнови профильный документ и `docs/08-product-workflow.md`.
- Не копируй секреты и не открывай credentials без нужды. Production живой: его состояние проверяй заново. Этот файл сам по себе не разрешает деплой, удаление данных или слияние PR.
- После структурных изменений обнови карту и этот файл, если изменился маршрут или устойчивый контракт. Не сохраняй здесь временный статус, номера миграций и хосты.

## Контракт рекомендаций и классификатора АСС

- Действующий источник каталога товаров — **https://www.aptekasosklada.kz** через backend ePharm. Medusa больше не используется как внешний источник; исторические идентификаторы и сохранённые снимки нужны только для совместимости существующих кампаний. Не возвращать запросы к старому Medusa origin и не подменять каталог Excel-классификатором.
- Для настройки замен использовать предоставленный пользователем [«Каталог АСС (1).xlsx»](</Users/amir/Downloads/Каталог АСС (1).xlsx>) как источник групп, подгрупп, МНН и связей товаров с ними. Не подменять его старой выгрузкой или придуманной классификацией; если файл недоступен, запросить копию. Новый источник принимать по явному указанию пользователя.
- Сохранять все четыре способа запуска рекомендации: **конкретный товар, группа АСС, подгруппа АСС и МНН АСС**. Работа с классификатором не должна убирать рекомендации по конкретному товару.
- Триггер и предлагаемые замены выбирать отдельно. Цены, наличие товаров и остатки проверять через действующий подключённый каталог и данные нужной аптеки; Excel с классификацией не заменяет эти данные.
- Совпадение группы, подгруппы или МНН — условие показа, а не доказательство медицинской взаимозаменяемости. Для замен отдельно проверять действующее вещество, дозировку, лекарственную форму и ограничения применения; не смешивать разные препараты только из-за сходства или сокращений названий.
- Указание источника в контракте само по себе не разрешает импорт в production, создание или массовую активацию правил: выполнять только действия, явно входящие в текущую задачу пользователя.
