# Сервис остатков Standard-N

## Назначение и границы

Исходники: [stock-service/](../stock-service/), тесты:
[stock-service-tests/](../stock-service-tests/). Это отдельный .NET 10 процесс на
сервере магазина. Он читает групповую Firebird 2.5 базу Standard-N, сохраняет
снимки в собственном SQLite и отдаёт их по JSON API. Веб-интерфейса и Excel нет.
POSM и HQ backend не меняются. Другой сервис подключается через Bearer API.

Источник аптек: `VW_G$PROFILES`, профили с `APTEKA_NUMBER IS NOT NULL`. Источник
положительных остатков: `WAREBASE_G`, строки с `QUANT > 0`. Партии не
агрегируются: цена, серия и срок годности относятся к конкретной строке.
`D$UUID` — первичный ключ исходной строки и `sourceId` в API. `PART_ID`
неуникален внутри аптеки и не может служить ключом партии. `profileId` в API —
ID Standard-N; ID аптек в HQ/Medusa нужно сопоставлять отдельно.

Firebird доступен через read-only учётную запись. Каждый параметризованный SELECT
идёт в транзакции `Read | ReadCommitted | RecVersion | NoWait` с таймаутом и
rollback после чтения. Пишет сервис только в собственный SQLite. Все профили,
включая помеченные в названии как закрытые, входят в обход: надёжного
формального признака закрытия в проверенной схеме нет.

## Сбор и честность свежести

Один фоновый работник синхронизирует список профилей и последовательно читает
каждую аптеку. Одновременно к Standard-N идёт максимум один запрос; циклы не
перекрываются. Новый снимок каждой аптеки публикуется одной транзакцией SQLite.
При ошибке старый снимок остаётся доступным со статусом `error`. После рестарта
прерванный цикл отмечается `interrupted`. Пропавший из источника профиль
исключается из активного каталога, но его старые строки не удаляются автоматически.

`STOCK_REFRESH_SECONDS=180` задаёт целевую свежесть и границу статуса
`fresh/stale`. `STOCK_SWEEP_INTERVAL_SECONDS` задаёт минимальный интервал между
стартами полных обходов; безопасное значение по умолчанию — 1800 секунд.
Когда обход длится дольше заданного интервала, новый старт откладывается минимум
на 180 секунд после завершения. API не скрывает отставание: `asOf`,
`lastSuccessfulRunAt`, число свежих/устаревших аптек и ход текущего цикла
доступны в `/api/v1/status`.

**Трёхминутная свежесть для каждой из 586 аптек сейчас не подтверждена.**
5 октября 2026 года безопасная последовательная проба 10 профилей прочитала
34 951 положительную строку за 11,8 с без записи в SQLite. Прямая экстраполяция
на 586 профилей — около 11,5 минуты только на чтение. Это оценка, не полный
нагрузочный тест. Запросы по `UPDATEDT` и `D$SRVUPDDT` получают план
`NATURAL`; у первого индекс неактивен, у второго его нет. Без подтверждённого
журнала изменений/реплики либо согласованного теста под наблюдением владельца
Standard-N сервис не ускоряет опрос параллельными соединениями и не заявляет
гарантированный SLA 180 секунд. При необходимости такой гарантии сначала
спроектировать поток изменений с учётом обнулений и удалений или проверить
нагрузку на изолированном источнике.

## API для интеграции

В корпоративной сети Caddy направляет
`https://inkeshopapteka.inkar.kz/stocks/api/v1/*` на внутренний контейнер,
срезая только `/stocks`. Прямой порт контейнера на хост не опубликован.
Все перечисленные маршруты требуют
`Authorization: Bearer <STOCK_API_KEY>`; ключ находится только в серверном
`stock-service/.env`. `/healthz` служит локальной проверкой процесса и не
публикуется через Caddy.

| Запрос                                                               | Ответ                                                                                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `GET /stocks/api/v1/status`                                          | Число профилей, fresh/stale/pending/error, статус и ход последнего обхода, время последнего успешного обхода. |
| `GET /stocks/api/v1/cities`                                          | Города и число активных профилей.                                                                             |
| `GET /stocks/api/v1/pharmacies?city=...`                             | Активные аптеки, `id`, `stockCount`, `lastUpdatedAt`, `status`.                                               |
| `GET /stocks/api/v1/pharmacies/{id}`                                 | Одна аптека или `404 pharmacy_not_found`.                                                                     |
| `GET /stocks/api/v1/pharmacies/{id}/stocks?limit=100&offset=0&q=...` | Партии, `total`, `asOf`, `snapshotId`; `limit` 1–500.                                                         |

Первый запрос партий возвращает `snapshotId`. При чтении следующей страницы
передавайте `snapshot=<snapshotId>`; если снимок успел смениться, ответ
`409 snapshot_changed` и чтение нужно начать заново. Пока первого снимка нет,
эндпоинт партий отвечает `503`, а не пустым остатком. `quantity` и `price`
передаются как JSON-числа, `expiryDate` — `YYYY-MM-DD` либо `null`.
Поиск `q` действует на весь снимок по имени и штрихкодам, регистр не учитывается
с учётом возможностей SQLite. Для устойчивой идентичности партии используйте
`profileId + sourceId`; `partId` не уникален.

Пример без настоящего ключа:

```bash
curl -H 'Authorization: Bearer <api-key>' \
  'https://inkeshopapteka.inkar.kz/stocks/api/v1/status'
curl -H 'Authorization: Bearer <api-key>' \
  'https://inkeshopapteka.inkar.kz/stocks/api/v1/pharmacies/1/stocks?limit=100&offset=0'
```

## Развёртывание, проверка и откат

На сервере рабочий каталог `/home/adm-quasar/stock-service` содержит код,
`compose.yml`, `.env` и `data/stocks.sqlite`. Git-ветка
`codex/pharmacy-stock-service` — передаваемый исходник. `.env` (права
`0600`) и `data/` не попадают в Git; владельцу интеграции нужно получить
Bearer-ключ через администратора сервера. Образ собирается через
`docker compose build`, запускается через `docker compose up -d`. Контейнер
работает без root, с read-only файловой системой, ограничениями CPU/RAM и без
опубликованного порта. Снимки в `data/` переживают рестарт.

Перед обновлением сохранить согласованный SQLite backup: остановить контейнер
и скопировать весь `data/`, либо использовать SQLite `.backup`. Не копировать
один `.sqlite` при активном WAL. Сохранить прежний образ и Caddyfile.
После запуска проверить `/healthz` из Docker-сети, 401 без Bearer, 200 с Bearer
на `/status`, список аптек и чтение снимка. `healthz` означает только живой
процесс; свежесть смотрите в `/status`. При откате вернуть прежний образ и
Caddyfile, а при несовместимости схемы — сохранённую копию `data/`.
Маршрут Caddy живёт в конфигурации релиза магазина; его нужно сохранять при
смене релиза (версии шаблонов лежат в `storefront/deploy/inkar-server/`).

Локальные проверки:

```bash
dotnet test stock-service-tests/stock-service-tests.csproj
dotnet publish stock-service/StockService.csproj -c Release
```

Для стороннего разработчика начните с
[README сервиса](../stock-service/README.md), `Program.cs` (HTTP-контракт),
`RefreshCoordinator.cs` (планировщик), `Source/StandardNSource.cs` (только
SELECT) и `StockRepository.cs` (SQLite/статусы).
