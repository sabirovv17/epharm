# Профили экранных плейлистов

## Задача

Большая часть рекламы одинакова для всей сети, но выбранным аптекам периодически нужен
отдельный набор роликов. Для этого используется два управляемых профиля:

- `pl_broadcast` - общий эфир для всех аптек;
- `pl_broadcast_targeted` - индивидуальный профиль для выбранного списка аптек.

Оба профиля имеют до 12 позиций. Индивидуальный профиль хранит только отличия от общего:
если его позиция не заполнена, POSM получает ролик из той же позиции общего эфира. Поэтому
HQ может оставить 90% общего контента и заменить только нужные ролики для выбранной группы.

## Поведение

1. Касса продолжает отправлять свой постоянный `pharmacyId` в запросе активного плейлиста.
2. Backend проверяет назначение аптеки в `playlist_pharmacy_assignments`.
3. Для неназначенной аптеки возвращается `pl_broadcast`.
4. Для назначенной аптеки backend объединяет общий и индивидуальный профиль по номерам позиций.
5. Собственный ролик индивидуального профиля перекрывает общий; пустая позиция наследуется.
6. POSM получает уже готовый упорядоченный список и не требует переустановки или нового конфига.
7. Текущий POSM опрашивает backend примерно каждые 20 секунд и скачивает изменившиеся ролики в кеш.

Legacy-плейлист, назначенный ровно одной аптеке по старой схеме, имеет более высокий приоритет.
Это сохраняет обратную совместимость во время перехода.

## Управление в админке

В разделе управления экранами доступны режимы `Общий для всех` и `Индивидуальный список`.

- В общем режиме замена позиции меняет эфир всей сети.
- В индивидуальном режиме HQ сначала выбирает аптеки, затем заменяет только нужные позиции.
- Метка `Из общего плейлиста` показывает наследованную позицию.
- Кнопка возврата к общему удаляет индивидуальное переопределение, не удаляя общий ролик.
- Сохранение списка аптек выполняется одной транзакцией: при неверном ID старые назначения остаются.

## Данные и миграция

Flyway `V038__targeted_screen_playlists.sql`:

- добавляет `playlists.parent_playlist_id`;
- создаёт `playlist_pharmacy_assignments`;
- создаёт управляемые профили, не перезаписывая существующий `pl_broadcast` и его слайды.

Production-манифест выбранных точек находится в
`ops/screen-playlists/targeted-pharmacies-2026-08-09.json`. В нём 97 подтверждённых строк,
95 уникальных `pharmacyId` и 11 адресов, которые нельзя назначать до уточнения. Повторы исходного
списка сворачиваются по `pharmacyId`.

## Проверка релиза

1. До deploy сохранить backup PostgreSQL и проверить количество/URL слайдов `pl_broadcast`.
2. После миграции убедиться, что старые слайды и объекты MediaStorage не изменились.
3. Назначить подтверждённые ID из манифеста профилю `pl_broadcast_targeted`.
4. Для назначенной аптеки запросить `/api/posm/playlists/active?pharmacyId=...`: идентификатор
   плейлиста должен быть `pl_broadcast_targeted`, а исходные ролики - отмечены как inherited.
5. Для аптеки вне списка должен вернуться `pl_broadcast` с теми же роликами.
6. Заменить тестовую индивидуальную позицию, проверить только выбранную аптеку и вернуть позицию
   к наследованию.

## Откат

Назначения можно удалить без изменения POSM: все кассы немедленно вернутся к общему эфиру при
следующем опросе. Удаление индивидуального override также безопасно возвращает общий ролик.
