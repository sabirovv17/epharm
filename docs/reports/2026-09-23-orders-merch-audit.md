## Review-находки и изменения в ветке

1. **P0 — QR + transport + demo accounts.** Подготовлен воспроизводимый patch отдельного merch SPA с относительными asset URL, mount-aware API/media/routing, восстановленным из работающего бандла отсутствующим `catalogCities.js` и тестами. ePharm Caddy ограничен точным allowlist staff-путей. Backend не отправляет ключ на публичный HTTP origin. Публичные demo admin credentials необходимо убрать из нового bundle без помещения их в Git; три соответствующие активные учётные записи требуют отзыва/ротации владельцем. Патч и исходные SHA — в `ops/merch-portal-patches/`.
2. **P1 — источник мерча не был в Git.** Патч хранится в ePharm, но полное приложение на 90.156.222.185 пока остаётся без собственного репозитория; любые будущие сборки требуют сверки базовых SHA и отдельного source-control решения.
3. **P1 — реальные деньги.** `paymentAuthority` нельзя добавлять по одному только значению браузера. Нужны согласованные server-verified событие оплаты, политика отмены/возврата и контракт обновления статуса после создания заказа. До этого карточная выдача остаётся fail-closed.
4. **P2 — изоляция offline-очереди.** Локальный кэш POSM теперь привязан к `(pharmacyId, deviceId)`, отвергает старый/чужой формат и восстанавливается после online poll; добавлены тесты смены аптеки и restart.
5. **P2 — установка/релиз.** Установщик POSM отвергает удалённый HTTP и некорректный явный SPKI, но сохраняет встроенный public key для legacy конфигов. Добавлены PowerShell preflight и release prepare→deploy contract tests.
6. **Открытые edge cases.** POSM при более чем 20 новых заказах за один poll показывает все в очереди, но уведомляет только о первых 20; повторяющаяся ошибка копирования обязательного POSM update может вызвать цикл рестартов. Нужны отдельные нагрузочный и Windows acceptance тесты.

## Go/No-Go для выкладки и демонстрации

Перед выкладкой: отозвать/ротировать три подтверждённые demo admin-учётки; GitHub PR с полными checks; проверенный backup исходников, `dist`, Caddy, env, БД и предыдущих образов; test/recreate Caddy с сохранённым rollback-файлом; смена merch upstream на проверенный HTTPS `:8443`; ротация ранее переданного по HTTP server key; снятие прямого публичного доступа к HTTP 8080 без нарушения согласованного доступа сотрудников. Нужен внешний телефонный тест с контролируемым token: HTML, JS/CSS, эталон, task API, фото, submit и понятная ошибка истечения. Для заказов нужен один новый cash/demo заказ после cutoff на двух действующих кассах, гонка `expectedVersion`, выдача по коду и возврат статуса на сайт. Эти пункты не должны подменяться одним только health/юнит-тестом.

При отказе: сначала откатить Caddy и его upstream, затем backend/frontend через предыдущие образы; merch `dist` и source — из проверенного backup. Не откатывать Flyway и не удалять outbox/заказы/задания. Любое повторение ошибки QR или bridge требует остановки дальнейшего rollout и read-only диагностики. Этот аудит сам по себе не является разрешением публиковать новую сборку или отзывать действующие учётные записи без согласования с владельцем.
