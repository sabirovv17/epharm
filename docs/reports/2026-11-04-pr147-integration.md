## Доработки по результатам проверки

- Обновлены устаревшие browser-ожидания названия поиска и явного раскрытия ИИН.
- LMS integration fixture проверяет отказ без `courses.create`, затем выдаёт это право
  до создания урока. Серверная авторизация не ослаблена.
- Финансовый fixture явно flush-ит JPA перед JDBC-вставкой резерва: внешние ключи
  проверяются по уже сохранённым фармацевтам, ограничения БД не отключаются.
- Согласованность сумм выплаты проверяется до SQL-отрицания: повреждённый BIGINT MIN
  даёт конфликт без изменения данных, а не PostgreSQL overflow.
- Добавлен PostgreSQL HTTP concurrency test: обе независимые транзакции действительно
  ожидают row lock; после освобождения возможны ровно 200 и 409, метаданные победителя
  сохраняются, кошелёк/проводки/резервы не меняются.
- В таблицах аптек и касс сохранены достижимые правые колонки; мобильное меню удерживает
  фокус, делает фон inert и возвращает фокус при закрытии.
- Раскрытие персональных полей привязано к ID аккаунта, роли и версии прав.

## Локальная проверка и ограничения

- 1103 frontend unit-теста успешны; после итоговой правки меню отдельно прошли 28
  navigation unit-тестов. Lint, TypeScript, production build и `git diff --check` успешны.
- На собранном интерфейсе прошли 71 browser-проверка, затем 9 целевых проверок с
  добавленным сценарием поиска. Восемь опциональных сценариев полной лаборатории
  требуют отдельного synthetic acceptance runtime и локально пропущены. Стандартный
  CI отдельно запускает backend integration, браузерные E2E и проверку готового образа;
  зелёный стандартный CI сам по себе не означает запуск этих восьми lab-сценариев.
- Целевые backend policy-тесты успешны; весь test source, включая новые PostgreSQL
  concurrency tests, компилируется. Docker daemon локально недоступен: PostgreSQL
  integration tests должны пройти в CI, рабочая БД для тестов не используется.
- CI на `b4693edf` подтвердил оба новых PostgreSQL concurrency/MIN_VALUE теста;
  отказ финансовых тестов воспроизведён как FK-ошибка их неподготовленного fixture.
  Исправленный fixture и точная итоговая ревизия требуют повторного полного CI.

Это отчёт о кандидате, не подтверждение выполненного выпуска. Обязательные следующие
ворота: зелёный CI точного PR и squash-main, official exact-main images, проверка source/
архивов/образов, изолированная копия БД и совместимый откат, свежий защищённый backup,
штатная two-image транзакция и проверка production. Точные SHA, CI и deployment receipt
фиксируются после выполнения. Отложенная настройка Sentry не подменяется фиктивными
ключами или отключением релизных проверок.
