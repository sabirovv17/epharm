# Руководство по тестированию обучения

Этот сценарий проверяет блок «Обучение» целиком: создание программы в админке, назначение
фармацевту, прохождение в мобильном приложении, фиксацию результата, выдачу сертификата и бонуса.

## 1. Подготовка локального окружения

Требуются Docker Desktop, JDK 22, Node.js 22+ и установленный Flutter SDK.

Из корня проекта запустите инфраструктуру:

```bash
docker compose up -d
docker compose ps
docker exec epharm-postgres pg_isready -U epharm -d epharm
```

В отдельном терминале запустите backend:

```bash
cd admin-panel/backend
export JAVA_HOME=/Users/amir/Library/Java/JavaVirtualMachines/temurin-22.0.2/Contents/Home
./gradlew bootRun
```

Проверка backend:

```bash
curl http://localhost:8080/api/health
```

В другом терминале запустите админку:

```bash
cd admin-panel/frontend
npm install
npm run dev
```

Админка откроется по адресу `http://localhost:5173`.

Если нужна чистая локальная демо-база, при работающем backend можно выполнить:

```bash
curl -X POST http://localhost:8080/api/admin/dev/reset
```

Команда предназначена только для профиля `dev` и удаляет текущие локальные демо-данные.

## 4. Базовый сквозной сценарий online

### Шаг 1. Подготовить онлайн-курс

1. Войдите в админку под `lms@epharm.kz`.
2. Откройте «Обучение» → «Онлайн-курсы».
3. Убедитесь, что есть хотя бы один курс со статусом «Опубликован». При необходимости создайте его.

### Шаг 2. Создать программу

1. Откройте вкладку «Программы» и нажмите «Новая программа».
2. Укажите название, например `QA Обучение online`.
3. Выберите формат `Онлайн` и опубликованный онлайн-курс.
4. Оставьте базовый маршрут: система создаст онлайн-этап и итоговую проверку.
5. Установите проходной балл `70`, две попытки и тестовый итоговый бонус, например `100` тенге.
6. Создайте программу и переведите её в статус «Опубликована».

Ожидаемый результат: программа отображается в реестре, у неё есть версия и маршрут для формата
`Онлайн`.

### Шаг 3. Назначить программу фармацевту

1. Откройте вкладку «Назначения» и нажмите «Назначить обучение».
2. Выберите созданную программу и формат `Онлайн`.
3. Найдите фармацевта, которому соответствует номер `+7 700 000 00 01`.
4. Задайте срок в будущем и выполните назначение.

Ожидаемый результат: появилась одна активная запись. Повторное назначение с политикой
«Пропустить» не должно создавать второй активный дубль.

### Шаг 4. Запустить мобильное приложение

Для iOS Simulator:

```bash
flutter run \
  --dart-define=USE_API=true \
  --dart-define=API_BASE=http://localhost:8080
```

Для Android Emulator:

```bash
flutter run \
  --dart-define=USE_API=true \
  --dart-define=API_BASE=http://10.0.2.2:8080
```

1. Войдите по номеру `+7 700 000 00 01` и коду `5445`.
2. Откройте «Профиль» → «Обучение».
3. Проверьте вкладки активных, завершённых и всех назначений.
4. Откройте программу и нажмите «Начать программу».
5. Откройте материал и подтвердите завершение доступного онлайн-этапа.

Ожидаемый результат: прогресс изменился, следующий обязательный этап стал доступен, а приложение
после pull-to-refresh показывает те же данные, что и админка.

### Шаг 5. Зафиксировать итоговую проверку

1. Вернитесь в админку, откройте «Результаты и экзамены».
2. Найдите назначение и этап итоговой проверки.
3. Нажмите действие фиксации результата, укажите `80` баллов и вариант «По проходному баллу».
4. Сохраните результат.

Ожидаемый результат:

- назначение завершено со 100% прогресса;
- в реестре появился один сертификат;
- начислен один итоговый бонус;
- в мобильном приложении появилось уведомление о завершении;
- повторная отправка результата не создаёт второй сертификат или второе начисление.

### Шаг 6. Проверить сертификат

1. Откройте вкладку «Сертификаты» в админке.
2. Откройте PDF сертификата.
3. Перейдите по публичной QR-ссылке сертификата.

Ожидаемый результат: PDF загружается, а публичная страница проверки возвращает номер сертификата,
фармацевта, программу, результат и дату выдачи без административной авторизации.

## 5. Сценарий hybrid/offline и QR

1. Создайте опубликованную программу с форматом `Гибридный` или `Офлайн` и очным этапом.
2. Во вкладке «Офлайн-мероприятия» создайте событие этой программы: будущая дата, город, адрес и
   вместимость больше нуля.
3. Назначьте программу фармацевту, привязав событие, либо дайте ему выбрать доступное событие в
   мобильном приложении.
4. В админке откройте QR-код события.
5. В мобильном разделе обучения откройте сканер и отсканируйте QR.
6. Во вкладке «Посещаемость» проверьте участника, оценку и комментарий тренера.

Ожидаемый результат: QR принимается только для подходящего назначения и события; статус
`Присутствовал` или `Опоздал` закрывает очный этап, а `Не явился` и `Уважительная причина` его не
завершают.

## 6. Проверка прав и устойчивости

Проверьте следующие случаи:

1. `BRAND_MANAGER` не видит учебные пункты и получает `403 FORBIDDEN` при прямом запросе учебного API.
2. `TRAINING_MANAGER` видит только «Обучение» и «AI-Экзаменацию»; прямой переход в `/rules`
   возвращает его в `/lms`, а запрос общего HQ API получает `403 FORBIDDEN`.
3. `HQ_HEAD` видит основные разделы, «Обучение» и «AI-Экзаменацию», но не видит управляющих кнопок;
   прямые учебные `POST`, `PATCH` и `DELETE` возвращают JSON `403 FORBIDDEN`, а экспорт доступен.
4. Изменение маршрута опубликованной программы создаёт новую версию; старое назначение остаётся на
   предыдущей версии.
5. Архивирование программы или курса не удаляет назначения, результаты и сертификаты.
6. Результат ниже проходного балла не завершает этап и учитывает использованную попытку.
7. Неподходящий или повторно использованный QR не создаёт дубликат посещения.
8. Региональный менеджер не получает данные аптек за пределами закреплённых регионов.
9. После временного отключения сети мобильный экран показывает ошибку с повтором; после
   восстановления сети pull-to-refresh возвращает актуальное серверное состояние.

## 7. Критерии приёмки

Базовый MVP обучения готов к приёмке, если одновременно выполняются условия:

- программа, маршрут, событие и назначение создаются из админки;
- фармацевт видит только свои назначения и не может менять назначенный формат;
- прогресс открывает этапы только в настроенной последовательности;
- результат экзамена и посещаемость принимаются только от разрешённой административной роли;
- завершение создаёт ровно один сертификат и одно начисление;
- сертификат открывается как PDF и проверяется по публичному QR;
- история сохраняется после архивирования;
- автоматические проверки из раздела 3 проходят.

## 8. Что не считать дефектом текущего MVP

Внешние push/SMS/email/WhatsApp-уведомления пока не отправляются: работает внутренний канал
приложения. Фактический AI-экзамен, контроль процента просмотра видео, автономная очередь действий
без интернета и XLSX/CSV-импорт назначений требуют отдельных интеграций. Их отсутствие не мешает
проверить основной маршрут обучения, описанный выше.
